# XAI Legal Risk Assessment (Synthetic Research Demonstrator)

A Streamlit academic demonstrator for black-box classifier explanations using DiCE, with a **separate synthetic hiring workflow** for Fairlearn fairness auditing. Both datasets are generated synthetic data; no real court, defendant, candidate, or hiring records are used.

> **Important:** Legal-risk categories are experimental labels generated by fictional rules. They are not actual judicial decisions, validated recidivism assessments, or recommendations. This application must not be used to make decisions about real people. Counterfactuals describe model behavior, not causal or guaranteed interventions. Compliance reporting is an assessment aid, not legal advice or certification.

## Features

- Separate synthetic legal-risk and hiring data workflows.
- Random Forest, Gradient Boosting, and Logistic Regression pipelines.
- Stratified held-out evaluation; preprocessing is fitted only on training data.
- Genuine DiCE counterfactual search for both synthetic datasets, with changed-feature display and model verification.
- Dataset-specific immutable features and permitted ranges, with validity, normalized proximity, sparsity, and diversity metrics.
- Fairlearn selection rate, true/false positive rates, demographic parity difference, and equalized odds difference for synthetic hiring groups, with 500-resample bootstrap intervals and selectable ThresholdOptimizer mitigation. The synthetic group attribute is excluded from the main model inputs.
- Plotly dataset, model, and group-metric charts.
- PDF transparency and regulatory-assessment report with limitations and human-oversight recommendations.
- Session-aware PDF sections for model, DiCE, and fairness artifacts, with a computed checklist and wrapped landscape tables.
- Streamlit multipage interface suitable for Community Cloud.

## Requirements

Use Python 3.11, 3.12, or 3.13. Runtime and test dependencies are listed in `requirements.txt`. DiCE and Fairlearn are constrained to their tested minor versions because their backend and mitigation APIs are used directly.


`python` must resolve to `.venv\Scripts\python.exe` after activation. Check with `python -c "import sys; print(sys.executable)"`. If it resolves elsewhere, use `.\.venv\Scripts\python.exe -m ...` or activate the app environment.

## Interpretation notes

- Legal labels are produced by a hand-written scoring rule plus random noise using seed 42. Accuracy measures recovery of that synthetic rule, not real-world predictive validity.
- Hiring data use seed 73. The referral-network score is an intentionally correlated synthetic proxy and is configured as non-actionable/immutable in the DiCE workflow.
- An optional local public-data inspection is available from Dataset Exploration. Place a user-supplied CSV in `data/` and explicitly map its columns to `age`, `prior_offenses`, `offense_category`, `employment_status`, and `risk_category`; for example, COMPAS-style sources may use `priors_count` and `c_charge_degree`. No dataset is downloaded. Verify source licensing and terms before use. COMPAS-related datasets have known bias controversies and require careful context; this is not endorsement or a validated public-data workflow.
- Model scores come from a stratified hold-out split and are recalculated by the training code; no performance values are embedded in the UI.
- The Model Training page adds stratified five-fold cross-validation and test-set permutation importance. A saved model artifact is loaded from `models/` when one exists; artifacts are local and ignored by Git.
- The hiring synthetic group attribute is present only for evaluation and is not a predictive feature.
- Fairness gaps are descriptive sample metrics and are sensitive to labels, thresholds, group definitions, and synthetic generation assumptions.
- Fairness metrics can conflict with one another and with accuracy; threshold mitigation does not prove real-world fairness. A group-in model is presented only as a separately labelled reference and is not recommended.
- DiCE counterfactuals respect dataset-specific constraints: legal-risk age and offense category are immutable, prior offenses stay within 0–6, and employment status stays within observed categories. The hiring synthetic group attribute is excluded from model inputs and cannot be changed.
- DiCE methods are user-selectable; integer features are rounded and re-verified with the fitted pipeline. Only counterfactuals that still flip the prediction are returned. Quality metrics describe the returned sample; normalized proximity is mean normalized change (lower is closer).
- This implementation is not a legal/clinical hiring system, a causal inference tool, or a GDPR/EU AI Act conformity assessment.

## Limitations and honest evaluation notes

- **Synthetic circularity:** legal outcome labels are generated by a hand-written scoring rule plus noise. High accuracy demonstrates recovery of that synthetic rule, not predictive validity for actual cases. The synthetic hiring outcomes and group relationship are also intentionally constructed.
- **Counterfactuals are not causal:** DiCE reports changes that flip the fitted model under configured constraints. It does not show that a real person could make those changes or that they would cause a real outcome.
- **Fairness trade-offs:** selection-rate, true-positive, and false-positive parity are distinct goals that can conflict with each other and accuracy. ThresholdOptimizer output and bootstrap intervals are sample-specific; mitigation does not prove real-world fairness.
- **Public data:** the optional Dataset Exploration mapping accepts a user-provided legal CSV only. COMPAS-related data have known bias controversies; confirm provenance, licensing, and permitted use. No public dataset is downloaded or bundled.

## Troubleshooting

- **`ModuleNotFoundError: dice_ml`:** check `python -c "import sys; print(sys.executable)"` and `python -m pip show dice-ml` after activation. If Python points outside this folder, activate `.venv` or use `.\.venv\Scripts\python.exe`. Install into the selected environment with `python -m pip install -r requirements.txt`.
- **NumPy/Pandas binary or resolver conflict:** use a fresh Python 3.11, 3.12, or 3.13 virtual environment and install the documented requirements together; avoid mixing global packages and `.venv`. Diagnose with `python -m pip check` and the full installation error.
- **Memory limits:** reduce the synthetic sample size or model complexity for local experiments; avoid launching multiple expensive model or DiCE runs simultaneously. The included UI does not fetch external data.
- **Slow DiCE generation:** request fewer counterfactuals, try `random` as the method, and expect genetic search to take longer. Results are only shown when verified against the fitted pipeline.
- **OneDrive file locks/sync conflicts:** close running Streamlit/Python processes and wait for sync to settle. To make a working copy outside OneDrive without deleting the original, run `New-Item -ItemType Directory -Force C:\StudentWork` and `robocopy "$PWD" "C:\StudentWork\XAI-Legal-Risk-Assessment" /E /XD .venv __pycache__ .pytest_cache`; then create a new `.venv` in that copy with `py -3.13 -m venv .venv` and reinstall dependencies.
- **PowerShell activation policy:** use the session-only command `Set-ExecutionPolicy -Scope Process Bypass`, or call the virtual-environment executable directly.
